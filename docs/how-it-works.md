# 工作原理

本文说明 Snug 的实现方式。构建、发布与代码结构见 [开发](development.md)。

## 连接判定

Snug 不接入 UU远程 的任何接口，只观察它在本机留下的三路信号：

| 信号 | 来源 |
| :--- | :--- |
| 覆盖窗口 | UU远程 在被控期间显示的窗口 |
| 控制端表格 | 通过辅助功能接口读取 UU远程 主窗口中「本机被控中」的列表，得到控制端名称与设备类型 |
| 推流事件 | 系统日志中 UURemoteServer 的屏幕捕获开始与停止 |

控制端表格只用作在场的证据：UU远程 仅在被控期间显示控制端列表，没有「无人控制」的界面。读不到控制端（例如主窗口停留在首页、错误页）不代表远程已经结束。

- **连入即时响应**：任一信号出现即视为连入。控制端不是电脑时创建手机屏；多台设备同时连接时，其中有一台不是电脑即创建；未识别出控制端时，等待 2 秒后按手机处理
- **断开从严判定**，以下两条同时满足才视为断开：
  1. 三路信号连续缺席 1.5 秒（UU远程 切换屏幕时，覆盖窗口会短暂重建）。推流仍在即视为远程仍在进行，不设时长上限
  2. 已过 Snug 自身加屏、撤屏后的 5 秒静默期（屏幕组合变化会让 UU远程 停流重开）
- **中途启动**：监听开始时先回看最近 4 小时的推流日志，远程进行中启动 Snug 也能正确识别
- **短暂断线**：断开后 15 秒内重新连接视为同一次远程，手机屏与屏上的窗口均保留。多台设备同时连接时，其中的手机、平板离开也同样等待 15 秒，仍未回来、只剩电脑时才移除手机屏

## 手机屏

- 通过 `CGVirtualDisplay` 创建竖屏；设置只提供红米 488×1084 与 iPhone 13 585×1266 两个基础尺寸，标准 1×像素，选择在下次建屏生效
- **多档分辨率**：从所选基础宽度到其两倍宽度，每 10 像素一档并包含精确上限，各档保留该设备宽高比；不强行请求不可用的 2× 模式
- 系统按其记忆的档位上线（首次为最宽一档），上线后切回基准宽度。换档交由短生命周期的辅助进程（`--set-mode`）完成；由主进程直接切换时，这块屏幕释放后需要 40 秒以上才能下线
- 创建或移除手机屏时被系统挤动的窗口，会被放回原处

## 窗口移动

- 以「启动会话 + 进程号/启动小数秒 + 系统窗口编号」识别窗口；位于其他桌面空间的窗口通过远程令牌定位
- 依次调整尺寸、位置、尺寸并核对结果，不符则重试
- 自动收拢不改变最小化、全屏和其他桌面窗口；资源库的显式选择仍保留上游特殊窗口处理
- 手机屏上的窗口被隐藏或关闭后，屏幕自动回到 App 资源库
- 辅助功能调用的超时设为 1 秒（系统默认约 6 秒），个别 App 卡住时不会拖慢整个界面

## App 资源库

手机屏的首页，分「运行中」与「全部」两页，顶部带搜索。

- **数据来源**：在运行的 App 取自 `NSWorkspace`（有 Dock 图标的），各自的窗口为辅助功能报出的全部标准窗口，不分屏幕与桌面空间，全屏、最小化的也算；本机 App 扫描三个「应用程序」目录及其下一层子目录，另加访达，排除菜单栏与后台 App、UU远程 和 Snug 自身。界面只读一处汇总（`AppCatalog`）；放窗口、等新窗口、等退出等动作直接读系统，确认 App 退完或窗口关上时立即从汇总中去掉
- **刷新**：列表露出时每 1.5 秒刷新一次运行中的 App。每次露出时按最近使用排序一次，此后只增删、不调换位置，避免点击时列表跳动；收起后停止刷新
- **打开与新建窗口**：打开用 `NSWorkspace.openApplication`，对已在运行的 App 即「重新打开」；新建窗口用辅助功能按下 App 菜单中的「新建窗口」，按标题识别（各 App 快捷键不同：Safari 为 ⌥⌘N，VS Code 为 ⇧⌘N，终端位于子菜单内），⌘N 只是新建一条记录的 App（日历、备忘录）不按。之后每 0.1 秒检查一次，此前不在屏上、此刻在屏上的标准窗口即为新窗口，立即放上手机屏（启动最多等 30 秒，其余 10 秒）。App 已有原生全屏窗口时，新窗口出生即进入全屏，动画结束前退出全屏的请求会被忽略，因此重复请求直到生效
- **退出**：先撤回焦点字号并把该 App 的原工作窗口归位，再请 App 退出，此后每 0.25 秒检查一次。出现「是否存储」对话框时（挂在窗口上的表单，或单独弹出的对话框），把它放上手机屏；10 秒仍未退出且没有对话框时，提示并提供强制退出。退出请求未能送达时立即提示。访达不提供退出，与 Mac 上一致
- **关闭窗口**：按下窗口自身的关闭按钮，等同点击红色按钮；原工作窗口先按会话基线归位，原生全屏的先退出全屏（全屏时按关闭按钮无效）。之后按退出的方式等待：出现「是否存储」时放上手机屏，5 秒仍未关闭且没有对话框时提示无响应
- **搜索**：匹配显示名、英文名、拼音全拼与首字母（如「bwl」匹配「备忘录」），同时搜索窗口标题。仅在搜索时由列表面板接收键盘，结束后交还
- **名称**：Snug 只声明简体中文，系统 App 显示为「访达」「备忘录」，与界面语言一致，不随系统语言变化

## 屏幕适配

手机屏的分辨率跟随屏上显示的内容：显示 App 资源库时为所选设备的基础宽度，显示窗口时为该窗口所需的一档。

- **按窗口实测**：放置窗口时先按基准宽度铺满。App 限定了最小尺寸时，窗口停在其最小尺寸上；按实际尺寸超出可放区域的比例（宽、高取较大者）选出能容纳它的最窄一档，切换后再次铺满。不按 App 预设
- **等比缩放**：各档宽高比相同，切换后画面整体等比缩小，不变形；UU远程 不重新推流，点击位置保持准确
- **切换开销**：约 0.4 秒，屏幕不掉线、编号不变。底部小横条与手势判定的阈值随档位放大，在手机上的大小与手感保持不变
- **上限**：最宽为基础宽度的两倍，此时字号约为基准的一半，与 UU远程 原版查看主屏相当。更宽的窗口按最宽一档靠左放置
- 回到 App 资源库时切回基准宽度；从列表返回窗口时，先切回该窗口的档位并重新铺满，再收起列表

## 还原记录

- 创建手机屏前完整捕获原布局，进入工作区前先写 `workspace.json`，它唯一拥有整会话的原始几何与桌面基线；切换焦点窗口不覆盖基线、不提前归还物理屏。
- `phone-screen.json` 只记录当前焦点窗口的临时铺满及字号增量；切换焦点先反转字号，窗口继续留在手机屏。
- 断开后撤屏、恢复原布局，连续两次读回位置/尺寸（误差不超过 1 点）和桌面归属后才清记录。进程启动身份变化才视为原窗口关闭；暂缺元数据会有界等待，失败保留原记录，阻止新会话覆盖。
- 锁屏先保留记录，解锁后自动继续；不把锁屏下不可读的窗口当成已关闭。旧的缺少强身份单窗记录保留并提示，不按未知身份重放。
- 自动收拢范围是捕获时可见普通窗口。原有特殊状态和其他桌面保持；连接后新开的窗口沿用上游单窗归还逻辑，不伪造不存在的连接前原位。

## 字号

- 通过 App 自身的 ⌘+ / ⌘- 调整，按键只发往该 App 的进程
- 放上手机屏时按该 App 记忆的级数放大（未记忆过则用设置中的默认级数），归位时按同样的级数缩回；不使用 ⌘0，以免清掉用户原有的字号
- 级数范围为 −4 至 +8，按 App 记忆在 `zoom.json`
- 支持 Ghostty、终端、iTerm2、VS Code、Cursor、Zed，以及已确认标识为 `com.openai.codex` 的 ChatGPT。该目标用 Command+Shift+Equal 表达 ⌘＋，其他既有应用保留 Command+Equal；缩小均为 Command+Minus。其他 App 中 ⌘= 可能另有含义，因此不发送
- 终端按标签页记忆字号：在手机屏上切换标签页后再还原，字号可能不一致
- 浏览器按网站记忆缩放，放大会连带同一网站的其他窗口，因此不调整；网页本身按窄屏排版

## 手势翻译

在独立线程上监听事件，只接管 UURemoteServer 注入、且在手机屏内按下的鼠标左键。本机的触控板、鼠标以及其他显示器不受影响。

| 手机上的操作 | 翻译为 |
| :--- | :--- |
| 移动不少于 10 点（基准宽度下，宽档按比例放大） | 带相位的像素滚动；松手后按速度附加惯性，速度设有上限 |
| 惯性滚动中轻点 | 仅停止滚动，不触发点击 |
| 按住 0.5 秒后拖动 | 补发按下事件，用于拖选文字 |
| 按住 0.5 秒后松开 | 右键 |
| 其余 | 原样放行 |

补发的事件带有标记，避免被再次接管。

## 启动与更新

用户手动打开 Snug，或在运行中再次打开时，弹出设置页；开机自启时不弹出。两者通过启动时 Apple Event 中的 `keyAELaunchedAsLogInItem` 区分。版本与上次运行时不同（应用内更新后重新打开、手动替换）时，改为打开设置窗口的「关于」页，显示新版本号。

每次启动检查一次所选更新源的 `update.json`（开机自启时等待网络连通），不轮询。有新版本时弹出更新窗口，由用户选择更新或稍后；启动时弹出的窗口不抢占当前 App 的键盘焦点：

1. 将已安装的 Snug.app 切块，按字节范围下载本机缺少的块，逐块核对 sha256
2. 在旁边拼出新版本，核对签名满足正在运行的这份的指定要求（同一应用标识与开发者团队），且版本号与 `update.json` 一致。辅助功能授权同样依据该要求，更新后无需重新授权
3. 与已安装的版本原子对调，经正常退出流程（窗口归位、撤除手机屏）退出，由独立进程等待退出后打开新版本

下载与拼装期间出现任何错误，已安装的版本都保持原样。所在位置不可写或不支持原子对调、`update.json` 格式更新、签名不符时，提示用户手动下载。

## 已知限制的技术原因

| 限制 | 原因 |
| :--- | :--- |
| 依赖未公开接口 | `CGVirtualDisplay` 是 macOS 的私有接口，系统大版本更新后可能变化 |
| 两个固定基础尺寸 | 红米 488×1084、iPhone 13 585×1266 标准 1×；更宽档位仍使用同一设备比例 |
| 部分窗口字号偏小 | App 自身限定了最小尺寸（系统设置宽 740 点、Safari 不小于 574 点），只能换用更宽的分辨率容纳窗口；超过所选设备两倍基础宽度的窗口靠左放置 |
| 字号放大仅限已支持应用 | 见上文「字号」 |
| UU远程 更新后可能受影响 | 控制端名称与设备类型从 UU远程 的界面读取，界面结构变化后可能无法读取 |
| 推流停止未被记录时，手机屏不会自动移除 | 推流状态来自系统调试日志，格式不是公开接口。此时菜单栏仍显示「远程中」，在设置中关闭手机屏即可还原；退出 Snug 只能暂时移除，4 小时内重新打开时，回看日志仍会判定为推流中 |
